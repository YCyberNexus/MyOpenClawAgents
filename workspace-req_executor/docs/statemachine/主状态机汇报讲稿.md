# req_executor 状态机讲稿

req_executor 的状态机围绕 GitLab issue 标签运行。`todo`、`new`、`retry` 会触发 fresh attempt；`continue` 会触发续跑；执行中是 `doing`；成功进入 `pr`；失败按侧区分为 `blocked-cc`、`failed-cc`、`timeout`、`blocked-dispatcher`、`failed-dispatcher`。

当前执行模型很简单：issue 内容就是 Claude Code 的任务提示。调度器只负责准备 `.req_executor` 运行目录、生成 prompt、启动 subagent、接收结果、同步标签和 MR。

如果任务需要额外账号、测试数据、环境说明或项目特定材料，应写在 issue 内容或仓库文件里，不再通过 req_executor 的触发字段传递。
